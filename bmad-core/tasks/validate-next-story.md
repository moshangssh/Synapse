# Validate Next Story Task

## 任务目标
验证用户故事草稿是否符合质量标准，确保故事具备可执行性和完整性。

## 执行步骤

### 1. 准备阶段
- [ ] 检查故事文件是否存在
- [ ] 验证文件格式（必须是 .md 或 .yaml）
- [ ] 加载故事模板进行对比

### 2. 基本信息验证
- [ ] 验证故事标题是否清晰明确
- [ ] 检查故事描述是否完整
- [ ] 确认优先级设置是否合理
- [ ] 验证估算值是否在合理范围内（1-8点）

### 3. 内容质量验证
- [ ] 检查用户故事格式（作为...我希望...以便...）
- [ ] 验证验收标准是否具体可测试
- [ ] 确认完成定义是否明确
- [ ] 检查是否包含必要的依赖关系

### 4. 技术可行性验证
- [ ] 评估技术实现复杂度
- [ ] 检查是否与现有架构兼容
- [ ] 验证是否需要额外的技术调研
- [ ] 确认是否涉及第三方依赖

### 5. 业务价值验证
- [ ] 评估业务价值主张
- [ ] 检查是否支持用户目标
- [ ] 验证是否与产品路线图一致
- [ ] 确认是否有助于解决核心问题

### 6. 风险评估
- [ ] 识别潜在的技术风险
- [ ] 评估时间风险
- [ ] 检查资源依赖风险
- [ ] 确认是否有备用方案

### 7. 交互式验证
- [ ] 与用户确认故事范围
- [ ] 讨论验收标准的合理性
- [ ] 评审估算的准确性
- [ ] 确认优先级设置

### 8. 生成验证报告
- [ ] 总结验证结果
- [ ] 提供改进建议
- [ ] 标记需要澄清的问题
- [ ] 确认是否可以进入开发

## 输出格式

### 验证结果分类
- ✅ **通过**: 故事质量良好，可以进入开发
- ⚠️ **条件通过**: 需要小调整后可以开发
- ❌ **需要修改**: 存在重大问题，需要重新编写

### 报告结构
```
# 故事验证报告

## 基本信息
- 故事ID: [ID]
- 标题: [标题]
- 优先级: [优先级]
- 估算: [估算]点

## 验证结果
[总体评估结果]

## 详细分析
### 优点
- [列出优点]

### 需要改进的地方
- [列出需要改进的地方]

### 风险提示
- [列出风险]

## 建议行动
[具体的建议行动]

## 最终决定
[通过/条件通过/需要修改]
```

## 质量检查清单

### 必须满足的条件
- [ ] 故事标题明确且可操作
- [ ] 包含完整的用户故事格式
- [ ] 验收标准具体且可测试
- [ ] 有明确的完成定义
- [ ] 估算值在1-8点之间

### 建议满足的条件
- [ ] 包含相关的依赖关系
- [ ] 有风险评估
- [ ] 与产品路线图一致
- [ ] 有明确的业务价值

## 常见问题及解决方案

### 问题1: 故事过于宽泛
**解决方案**: 将大故事拆分为多个小故事，每个故事聚焦于一个具体的功能点。

### 问题2: 验收标准不明确
**解决方案**: 使用GIVEN-WHEN-THEN格式重写验收标准，确保每个标准都可以被测试。

### 问题3: 估算不准确
**解决方案**: 与开发团队讨论，参考类似故事的估算，调整估算值。

### 问题4: 缺少业务价值
**解决方案**: 明确故事要解决的用户问题，量化预期收益。

```
2. [方案2]
3. [方案3]

您希望如何处理这个问题？
```
