### **故事标题**

后端实现查找和替换功能 (V2)

* **优先级 (Priority):** High
* **工作量估算 (Estimate):** 5 故事点
* **状态 (Status):** Ready for Review

### **用户故事**

**作为一名** 开发人员，
**我希望** 将查找和替换逻辑迁移到后端处理，
**以便于** 集中管理文本处理逻辑，未来更容易扩展，并减轻前端在处理大量字幕时的计算负担。

### **故事背景**

* **系统集成点:**
    * **前端:** 需要修改 `src/hooks/useFindReplace.ts` 中的 `handleReplaceAll` 函数。
    * **后端:** 需要在 `main.py` 中创建一个新的 API 端点，并在 `text_utils.py` 或类似模块中添加新的处理函数。
* **技术栈:**
    * **后端:** Python, FastAPI
    * **前端:** React, TypeScript, Zustand
* **参考模式:** 新的后端端点应遵循现有 `/api/v1/subtitles/remove-filler-words` 端点的实现模式。

### **验收标准 (Acceptance Criteria)**

1.  **[后端]** 创建一个新的 POST API 端点：`/api/v1/subtitles/replace-all`。
2.  **[后端]** 该端点接受一个请求体，包含字幕列表 (`subtitles`)、搜索查询 (`searchQuery`) 和替换文本 (`replaceQuery`)。
3.  **[后端]** 后端逻辑对所有匹配 `searchQuery` 的字幕文本执行全局、不区分大小写的替换操作。
4.  **[后端]** 端点返回更新后的完整字幕列表，其中只包含被修改字幕的 `id` 和新的 `text` 字段。
5.  **[前端]** `src/hooks/useFindReplace.ts` 中的 `handleReplaceAll` 函数被重构，以调用新的后端 API 端点。
6.  **[前端]** `useDataStore` 状态能够根据后端返回的数据正确更新匹配字幕的 `text` 和 `diffs` 字段。
7.  **[前端]** 在调用 API 期间，UI 应显示一个加载指示器（例如，按钮变为禁用并显示加载状态），并在操作完成后移除。
8.  **[集成验证]** 在前端 UI 上执行“全部替换”操作时，功能与之前完全一致。
9.  **[性能]** 在测试环境中，处理1000条字幕的替换操作，API 响应时间应在2秒内完成。
10. **[错误处理]** 如果 `searchQuery` 为空，API 应返回一个带有明确错误信息的 400 Bad Request 响应。
11. **[边界情况]** 后端能正确处理搜索查询中包含的正则表达式特殊字符（例如 `.`、`*`、`+`），应将它们作为普通文本进行匹配。
12. **[数据完整性]** 替换操作确认不会以任何方式破坏字幕的 `id`、`startTimecode` 或 `endTimecode` 信息。

### **技术说明**

* **API 契约 (Request/Response):**
    * **请求 (Request Body):**
        ```json
        {
          "subtitles": [
            { "id": 1, "text": "...", "originalText": "..." }
          ],
          "searchQuery": "string",
          "replaceQuery": "string"
        }
        ```
    * **响应 (Response Body):**
        ```json
        {
          "status": "success",
          "data": [
            { "id": 1, "text": "updated text..." }
          ]
        }
        ```
* **正则表达式处理:** 后端在执行替换前，必须对传入的 `searchQuery` 进行转义，以确保所有字符都被视为字面量。
* **`diffs` 字段处理决策:**
    * **后端** 只负责文本替换的核心逻辑，并返回修改后的字幕 `id` 和 `text`。
    * **前端** 在收到成功的 API 响应后，负责遍历返回的数据，并使用现有的 `calculateDiff` 工具函数，根据 `originalText` 和新的 `text` 重新计算并更新 `diffs` 字段。这确保了前后端职责分离。
* **批量操作:** 此 API 设计天然支持批量操作，因为它接受完整的字幕列表。
