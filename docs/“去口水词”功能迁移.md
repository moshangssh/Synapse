### **用户故事 (v3 - 已修订): 将“去口水词”功能迁移至后端并支持自定义标点**

**状态**: Approved

**故事**

作为一名 **开发人员**，我想要 **将“去口水词”的处理逻辑迁移到后端API，并让用户可以通过配置文件定义不被移除的标点符号**，以便于 **减轻前端负载，集中管理逻辑，并提供更灵活的文本清理选项**。

**验收标准 (Acceptance Criteria)**

1.  **配置文件更新**: `public/filler_words.json` 文件必须增加一个新的 `preserved_punctuation` 键，其值为一个包含书名号（`《` `》`）和引号（`“` `”`）等符号的字符串数组。
2.  **后端API实现**: 必须在FastAPI后端创建一个新的POST API端点（例如 `/api/v1/subtitles/remove-filler-words`），该端点：
    a.  接受包含字幕列表和`removePunctuation`布尔值的JSON负载。
    b.  能读取并使用 `filler_words.json` 中的 `words` 和 `preserved_punctuation` 列表进行处理。
    c.  当 `removePunctuation` 为 `true` 时，能移除**除了** `preserved_punctuation` 列表中定义的所有标点符号。
    d.  返回处理后带有差异（diffs）信息的字幕列表。
3.  **前端逻辑重构**: 前端组件 `FillerWordRemover.tsx` 中的本地处理逻辑必须被完全移除，并替换为对新后端API的调用。
4.  **状态管理**: 前端 `useDataStore` 状态管理库必须能被后端返回的数据正确更新。
5.  **用户体验**:
    a.  从用户角度看，功能表现（包括“撤销”功能）必须与迁移前完全一致。
    b.  前端必须能处理API调用失败的情况，并向用户显示错误通知（使用 `useNotifier`）。
6.  **回归验证**: 应用的所有其他现有功能必须不受此次修改的影响。

**任务分解 / Subtasks**

* [ ] **任务 1: 后端 API 开发** (AC: #1, #2)
    * [ ] 1.1: 更新 `public/filler_words.json` 文件，添加 `preserved_punctuation` 字段。
    * [ ] 1.2: 在 `schemas.py` 中为新端点创建 Pydantic 请求/响应模型。
    * [ ] 1.3: 创建一个新的工具函数（例如在 `text_utils.py` 中）来实现核心的文本清理逻辑。
    * [ ] 1.4: 在 `main.py` 中添加新的 `/api/v1/subtitles/remove-filler-words` 端点并集成处理逻辑。

    * [ ] 2.1: 重构 `FillerWordRemover.tsx`，移除本地正则表达式逻辑，替换为使用 `fetch` 的API调用。
    * [ ] 2.2: 在 `useDataStore.ts` 中调整状态更新函数，以处理来自后端的字幕数据。
