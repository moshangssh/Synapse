## Story

**I want** to conveniently trigger AI optimization on the main interface and provide optional context information,
**so that** I can easily start the optimization process.

### Data Models
- **Subtitle**: From `frontend/synapse/src/types/index.ts` - contains id, text, startTime, endTime, and other subtitle properties [Source: frontend/synapse/src/types/index.ts]
- **OptimizationRequest**: From backend schemas - requires subtitles array, reference_info (optional), batch_size, model, temperature, max_tokens [Source: backend/schemas.py]
- **OptimizationResponse**: From backend schemas - contains data array of OptimizedSubtitleItem and metadata [Source: backend/schemas.py]
- **OptimizedSubtitleItem**: From backend schemas - contains id, original_text, optimized_text, and diffs array [Source: backend/schemas.py]
- **SettingsState**: From `frontend/synapse/src/stores/useSettingsStore.ts` - contains API configuration (apiEndpoint, apiKey) for LLM service calls [Source: frontend/synapse/src/stores/useSettingsStore.ts]

### API Specifications
- **Backend optimization endpoint**: `POST /api/v1/optimizer/optimize` - requires OptimizationRequest with subtitles array and optional reference_info [Source: backend/routers/optimizer.py:168]
- **Request format**: JSON with subtitles array, reference_info (string, optional), batch_size (int, default 10), model (string, default "gpt-3.5-turbo"), temperature (float, default 0.7), max_tokens (int, default 2000) [Source: backend/schemas.py]
- **Response format**: OptimizationResponse with data array and metadata including processing_time, cache_stats, and error counts [Source: backend/routers/optimizer.py:221]
- **Error handling**: Backend returns ErrorResponse with consistent error structure and HTTP status codes [Source: backend/schemas.py]
- **Configuration integration**: Must use existing API configuration from useSettingsStore for endpoint and API key [Source: frontend/synapse/src/stores/useSettingsStore.ts]
